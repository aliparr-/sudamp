# Spike R1: yt-dlp delivery and resolver (PLAN M0)

cookies; yt-dlp 2026.10.21). Every criterion measured here passes. Two PLAN R1 items are **not covered by this
report**: `sudamp-dev play-url` first audio per source (run by the orchestrator from the saved resolutions below)

`yt-dlp_macos -J` through `ResolverService` (debug build). YouTube budget: **38 of 40** requests used (1 search,
3 × 11 resolves, 2 error captures, 2 raw-JSON captures), spaced ≥ 3 s apart. No bot check was seen.

Install timings (fresh profile, `engine-install.json`): 53.9 MB download 0.97 s, unpack (`ditto -x -k --noqtn`)

`release-assets.githubusercontent.com`. The SHA matched, and `metrics.jsonl` logged `engine.download.resume`.

## Plugin-isolation canary

`Fixtures/ytdlp/plugin-canary/run.sh` plants a marker-writing extractor plugin in each location
`yt_dlp/plugins.py default_plugin_paths()` searches:

- the real `~/.config/yt-dlp/plugins`, `~/.yt-dlp/plugins`, `~/.config/yt-dlp-plugins` and `~/yt-dlp-plugins`;
- the same four under sudamp's `engine-home`;
- `yt-dlp-plugins/` next to the executable;
- the frozen `sys.path` roots `_internal/` and `_internal/lib-dynload/`.

That is 11 plants. The script refuses to run if any target already exists, and an EXIT/INT/TERM trap removes only
the directories it created. Result (`pass: true`):

- **Positive controls** (no isolation flags, no `YTDLP_NO_PLUGINS`, probe URL `sudamp-canary-probe:x`, offline).
  With the real HOME, 6 markers fired: the 4 user dirs, `exe-dir`, `_internal`. With `HOME=engine-home`, 6 fired:
  the 4 engine-home dirs, `exe-dir`, `_internal`. So 10 of the 11 plants are real load paths. `lib-dynload` never
  loaded (it isn't a plugin root in this build).
- **The real `sudamp-dev resolve`** (SoundCloud, exit 0, media host `playback.media-streaming.soundcloud.cloud`):
  **0 markers**.
- **Each layer alone, with the real HOME:** `YTDLP_NO_PLUGINS=1` only gave 0 markers, and `--no-plugin-dirs` only
  gave 0 markers. Either layer suffices; sudamp uses both plus the private HOME.
- **Cleanup verified.** 0 directories left, 0 `sudamp_canary_*` files left. `~/.config/yt-dlp`, `~/.yt-dlp`,
  `~/.config/yt-dlp-plugins` and `~/yt-dlp-plugins` are absent again, as they were before. The engine tree
  re-verifies.
- **Not planted:** `/etc/yt-dlp/plugins` and `/etc/yt-dlp-plugins` (they need root). Both layers block every
  default location regardless of path.
- `--list-extractors` turned out to be useless as a trigger: `print_extractor_information` returns before
  `_load_all_plugins()` in `_real_main`.
- `EngineTree.verify` also reports **unexpected** files. A plugin planted next to the executable or in
  `_internal/` fails the launch re-hash.

## Findings

- **Media-host suffixes** (media URLs and every HLS segment line checked):
  - YouTube VOD: `rr*---sn-*.googlevideo.com`.
  - YouTube `/live`: manifest on `manifest.googlevideo.com`, segments on `rr*---sn-*.googlevideo.com`.
  - SoundCloud: playlist and segments on `playback.media-streaming.soundcloud.cloud`.
  - Mixcloud: `dl.mixcloud.stream` (progressive `http`) and `aod.mixcloud.stream` (HLS/DASH; segments too).
  - Defaults are therefore `googlevideo.com`, `media-streaming.soundcloud.cloud` and `mixcloud.stream`
    (`ResolverSettings.defaultMediaHosts`). A CDN move fails as `engine/mediaHost` until the feed lists the new
    host.
- **Nightly onedir exists.** `yt-dlp/yt-dlp-nightly-builds` latest is `2026.10.21.233146`, with `yt-dlp_macos.zip`,
  `yt-dlp_macos`, `SHA2-256SUMS` and `_update_spec`. `sudamp-dev engine install --channel nightly` installed it:
  134 files, SHA matches its SUMS, `--version` prints `2026.10.21.233146`, cold 1.37 s, warm 174 ms. **Nightly
  escalation can stay in M6.**
- **`soundcloud:formats=hls_aac` changes nothing on today's catalogue.** The extractor makes one api-v2 request per
  transcoding that matches `formats` (default `http_aac, hls_aac, http_opus, hls_opus, http_mp3, hls_mp3`). The
  tested tracks only expose `hls_aac_96k`/`hls_aac_160k`, so with and without the argument the requests (info,
  original-download info, 2 × hls_aac info, thumbnail) and the formats were identical. p50 was 582 vs 632 ms, which
  is noise. It still prunes requests for any track that keeps MP3/Opus transcodings, so it stays.
- **`available_at` is not always present.** YouTube progressive formats carry it (it equalled extraction time at
  both tiers, so there was no ad wait). YouTube live HLS formats and SoundCloud/Mixcloud formats have none.
  `ResolvedStream.wait(now:)` treats nil as 0. DESIGN §6.3 says "always present".
- **Expiry.**
  - YouTube VOD and `/live`: +6 h (`expire=` in the query or the `/expire/<t>/` path).
  - SoundCloud: **+2.8 h** today (`expires=`; research measured 4.9 h). The cache follows the URL, not a constant.
  - Mixcloud: none (progressive URLs carry only `sig=`).
- **Mixcloud quality varies by upload.** Older uploads offer only `hls-64/70/71` (no `hls-192`), so the default
  `hls-192/http/bestaudio` falls back to progressive `http`: 64 kbit/s m4a with `http_chunk_size` 5 MiB, which needs
  `request_size`. Newer uploads (NTS) offer `hls-192`. If HLS is preferred at equal bitrate,
  `hls-192/bestaudio[protocol^=m3u8]/http/bestaudio` passes §7.2 validation. The default is unchanged pending a
  DESIGN decision.
- **Tier-1 YouTube prints no warnings.** The "extraction without a JS runtime has been deprecated" warning isn't
  printed with an explicit `--no-js-runtimes`. SoundCloud prints "Original download format is only available for
  registered users" on every resolve; it's harmless and logged at notice level.
- **The real `_update_spec` identifier** (from `-v`) is `darwin_dir Python 3.14.7 (CPython arm64 64bit) -
  macOS-27.0.1-arm64-arm-64bit-Mach-O (OpenSSL 3.5.7 9 Jun 2026)`. No lock line in 2026.10.21's `_update_spec`
  matches it, or the synthesised first-install identifier.
- **Timeout precision.** The first version used `DispatchQueue.asyncAfter`, which GCD may coalesce: a 10 s kill
  slipped past 10.3 s, and yt-dlp's own 10 s socket timeout fired first. `Subprocess` now waits on kqueue
  (`EVFILT_PROC`/`NOTE_EXIT` with an exact timeout). A black-hole proxy run is killed at **10,003 ms**, classified
  `transient/timeout`, and no `yt-dlp_macos` or `qjs` process remains.
- **Classifier gap found live.** A missing YouTube video says "This video is unavailable", not "Video unavailable".
  It is fixed, and the real stderr is a fixture (`captured-yt-missing-live.txt`).

## Behaviour as built

- **Choosing a version** (`EngineChooser`, `EngineStore.choose`):
  - `block` is always honoured, and invalid pin/block values are dropped (§7.2 rules).
  - `pin` wins if it is valid, not blocked and not above an `_update_spec` lock.
  - Otherwise `releases/latest` is used, read from the redirect (no REST API).
  - If latest is blocked or above a lock, the newest allowed tag from `releases.atom` is used.
- **`_update_spec`** follows `update.py _process_update_spec`:
  - `lockV2` lines for our repo are used if any exist, else `lock` lines;
  - lines apply in file order, matching the identifier's start like `re.match`;
  - the first match caps the version.
  - Before the first install the identifier is synthesised without a Python version, so only variant/OS locks can
    match. M6 can pass the engine's real `-v` identifier.
- **Install steps:**
  1. Check free space: ~180 MB minus what the `.partial` already holds.
  2. Fetch `SHA2-256SUMS`.
  3. Download the zip with resume into `engines/yt-dlp/<ver>.partial/`.
  4. Verify the SHA-256 against `pin.sha256` (when pinned) or upstream SUMS. A mismatch deletes the zip.
  5. Unpack with `ditto -x -k --noqtn` and scan for quarantine.
  6. Write `tree.json` (path, octal mode, size, SHA-256; symlink targets recorded, not followed).
  7. Smoke-test `--version`: 1 cold and 3 warm runs, with output equal to the version.
  8. Move into `engines/yt-dlp/<ver>/` and switch `current.json` atomically, recording `previous`.
  9. Prune everything except current and previous.
- **Invocation** is exactly DESIGN §6.2 (golden tests in `InvocationTests`). One deliberate choice: `/live` also
  gets the ladder's `--extractor-args youtube:player_client=<tier clients>` (tier 1 `visionos`), because the JS
  ladder applies to both YouTube kinds and pinning the client keeps the call deterministic if upstream's JS-less
  default changes. It measured within target.
- **ResolverService:**
  - It is serial. A `.user` request kills an in-flight `.background` one, which throws `preempted`.
  - Waiters are served by priority, then arrival. A cancelled caller kills the process group.
  - `resolveWithLadder` steps up to tier 2 only on engine-class failures; a bot check never costs a second
    YouTube request.
  - Successful results are rejected when the media host isn't allowlisted (`engine/mediaHost`) or the format is a
    SoundCloud preview (`unavailable/preview`).
- **Classifier.** Rules are checked in order (botCheck, unavailable, transient, engine), against the `ERROR:` line
  first and then all of stderr. Anything unknown is `engine/unknown`. There are 33 fixtures: 28 built from yt-dlp
  2026.10.21 source strings and 5 captured live.
