# Spike R2: Plan B costing (PLAN M0)

**Verdict: information only (no GO/NO-GO).** Measured 2026-10-22 on macOS 27.0.1, M5 Pro, residential broadband, no cookies, no curl_cffi in plan B. All work was done in `/tmp/sudamp-r2`; nothing was installed system-wide.

**Bottom line.** Plan B is viable and cheaper than expected. A trimmed python-build-standalone runtime adds **14 MB compressed / 39.5 MB on disk** to the app, with **1–2 Mach-O files** to sign (`python3.14`, plus `_dbm.so`, which yt-dlp doesn't use). The engine then becomes a **3.07 MB** pure-Python download instead of 53.9 MB / 107 Mach-O files. Warm start is **67 ms vs onedir's 165 ms**, provided the zipapp is unpacked and pre-compiled at install time. HTTPS works out of the box. SoundCloud, Mixcloud and one JS-less YouTube resolve all worked without curl_cffi, at onedir-like speed. The real cost is losing browser impersonation: Mixcloud already prints a warning about it, although it still resolved.

## Start-up: `--version`

Each run used a scrubbed environment (DESIGN §6.2 shape: `env -i HOME=… PATH=/usr/bin:/bin LANG=… YTDLP_NO_PLUGINS=1`). "First" is the first run after a fresh extraction. The OS file cache could not be flushed (`purge` needs root), so "first" here means no bytecode cache yet, not a disk-cold start. "Warm" is the median of n = 10, with min–max in brackets.

| Configuration | First | Warm p50 |
|---|---|---|
| 3.14 `-I -B <zipapp>` (no .pyc anywhere) | 611 ms | 425 ms (421–431) |
| 3.14 `-I -X pycache_prefix=<dir> <zipapp>` | 451 ms | 242 ms (241–246) |
| 3.14 `-I -X pycache_prefix=<dir> <unpacked zipapp dir>` | 371 ms | 65 ms (64–66) |
| 3.13 `-I -B <zipapp>` | 672 ms | 393 ms (390–395) |
| 3.13 `-I -X pycache_prefix=<dir> <zipapp>` | 417 ms | 227 ms (225–231) |
| 3.13 `-I -X pycache_prefix=<dir> <unpacked dir>` | 344 ms | 62 ms (61–63) |
| **Trimmed 3.14 + stdlib .pyc, `-I -B <unpacked dir with checked-hash .pyc>`** (read-only, the shape to ship) | 68 ms | **67 ms (66–70)** |
| Trimmed 3.14 + stdlib .pyc, `-I -B <zipapp>` | — | 243 ms (242–246) |
| **Onedir `yt-dlp_macos`** (same harness) | **1,592 ms** | **165 ms (164–169)** |

Why it behaves like this:

- **zipimport never caches bytecode.** Run as a single file, the zipapp recompiles every yt_dlp module it imports on every run, including `lazy_extractors.py` (782 KB). With a pycache prefix, 163 stdlib modules were cached and 0 yt_dlp modules. That costs a fixed ~180 ms per call.
- **Unpacking and pre-compiling at install time** removes that cost and makes plan B **2.5× faster than onedir** at start-up. The unpacked tree is pure data, so it can get the same `tree.json` re-hash treatment as onedir (DESIGN §6.1 step 4). Compile it with `--invalidation-mode checked-hash` so Python checks each `.pyc` against its source's hash on import: Application Support is user-writable, and timestamp-based pycs could be swapped silently. The checked-hash cost is included in the 67 ms.
- **`-I` ignores every `PYTHON*` environment variable.** The recipe in docs/research/shell.md ("`-I -B` with `PYTHONDONTWRITEBYTECODE=1`") works only because of `-B`, and `PYTHONPYCACHEPREFIX` would be ignored. Use the flags `-B` / `-X pycache_prefix=<Caches>/…` instead. With `-B` and shipped pycs, **0 files** were written into the runtime or engine trees across all runs (checked with `find -newer`), so the app's signature seal is safe.
- **3.13 vs 3.14:** 3.13 is 15–32 ms faster when bytecode is recompiled on each call, but only 3 ms faster in the unpacked, pre-compiled shape we'd ship. Take 3.14 (onedir also bundles 3.14).
- `python -I <zipapp>` works: `-I`'s safe-path rule doesn't stop a zipapp or directory from putting itself on `sys.path`.

## TLS

| Setup (3.14, OpenSSL 3.5.9) | soundcloud.com / mixcloud.com / github.com | expired / self-signed badssl.com |
|---|---|---|
| **Out of the box** | OK | `CERTIFICATE_VERIFY_FAILED`, as it should be |
| `SSL_CERT_FILE=/etc/ssl/cert.pem` | OK | — |
| `SSL_CERT_FILE=/nonexistent` | all fail (`unable to get local issuer certificate`) | — |
| certifi 2026.10.19 in `site-packages` | OK | expired fails; self-signed was a connection reset (a transient badssl issue) |

- **HTTPS works with no configuration.** PBS's OpenSSL has `OPENSSLDIR` defaulting to `/private/etc/ssl` (`cafile=/private/etc/ssl/cert.pem`, the macOS-shipped bundle of 128 roots, updated with the OS). The worry in docs/research/shell.md ("standalone OpenSSL may not find macOS root certificates") does not apply to PBS 20261021.
- `SSL_CERT_FILE` is an OpenSSL variable, so it **is** honoured under `-I`. The `/nonexistent` row shows there's no other fallback.
- yt-dlp uses certifi whenever it can import it (`Optional libraries: certifi-2026.10.19` in `-v`). Otherwise it calls `load_default_certs()`, which reads the system bundle. A SoundCloud resolve worked both ways, and with no CA store it failed cleanly with `CERTIFICATE_VERIFY_FAILED`.
- **Limitation (same as onedir, which bundles certifi):** neither path reads the Keychain. Roots added by the user or MDM (corporate TLS inspection) aren't trusted, so resolves fail where Safari works. The `truststore` package (Security.framework) would fix it [untested].
- **Recommendation:** rely on the system bundle and don't ship certifi. It is MPL-2.0 data that we'd have to keep current, and `/etc/ssl/cert.pem` is maintained by OS updates. Keep `SSL_CERT_FILE` out of the scrubbed environment.

## Resolves without curl_cffi

The zipapp under PBS reports `Optional libraries: sqlite3-3.53.1, yt_dlp_ejs-0.8.0` and `Request Handlers: urllib`. That means no curl_cffi, requests, urllib3, websockets, brotli, certifi, mutagen or pycryptodomex. Onedir reports all of them, with handlers `urllib, requests, websockets, curl_cffi`. Flags follow DESIGN §6.2 (`--ignore-config --no-plugin-dirs --no-update --no-js-runtimes --cache-dir … --no-playlist --socket-timeout 10 -J` plus each source's flags). "First" uses a fresh `--cache-dir`, so it includes SoundCloud's client_id scrape, and runs with `-v`. "Warm" is n = 5, p50 (min–max).

| Source | Plan B unpacked (3.14 + pycache prefix) | Plan B zipapp file (3.14 `-B`) | Plan B shipping shape (trimmed, `-B`, read-only) | Onedir |
|---|---|---|---|---|
| SoundCloud, first | 661 ms | 1,192 ms | 759 ms | 734 ms |
| SoundCloud, warm | **493 ms** (477–510) | 906 ms (879–942) | **532 ms** (475–585) | 561 ms (526–670) |
| Mixcloud, first | 951 ms | 1,518 ms | — | 785 ms |
| Mixcloud, warm | **675 ms** (674–820) | 1,120 ms (1,065–1,572) | **770 ms** (625–926) | 858 ms (780–1,464) |

- **SoundCloud** ([a 2 h 59 min mix](https://soundcloud.com/vibeydeephouseradio/vibey-deep-house-mix-2025-mix-by-fleiv-selected-mix-2025-deep-house-mix-2025-ibiza-house-mix-2025-10-17)): the request sequence is identical to onedir's (main page, JS asset, info JSON, 2 × hls_aac format info). It selects `hls_aac_160k` (AAC, `playback.media-streaming.soundcloud.cloud`), the m3u8 fetches 200, and there are no impersonation warnings.
- **Mixcloud** ([a 79 min mix](https://www.mixcloud.com/maestrosdelritmo/maestros-del-ritmo-volxxx-the-masterpiece-top-100-2012-2018/), the top of `api.mixcloud.com/discover/deep-house/popular/`): it works, but prints `WARNING: [mixcloud] The extractor is attempting impersonation, but no impersonate target is available`. The offered formats are identical with and without curl_cffi (`http`, `hls-70`, `dash-a1-x3`). **This mix offers no `hls-192`**, so DESIGN §6.2's `hls-192/http/bestaudio` falls through to `http` (progressive m4a at `dl.mixcloud.stream`; a range GET returned 206) in both flavours. R1 should check how common that is.
- **YouTube, one JS-less resolve** (`--extractor-args youtube:player_client=visionos`, DESIGN's VOD format string, `K6XiDub2Wc4`, plan B unpacked): **1,288 ms**, 42 formats, audio itags 233 234 139 249 250 140 251. It selected 251 (opus ~131 kbps) and a 1 KB range GET returned 206 `audio/webm`. YouTube budget used: **4 of 5 requests** (webpage, visionos player API, m3u8 info, plus one googlevideo range GET).
- **Hardened runtime:** an ad-hoc `codesign --options runtime` copy of the trimmed `python3.14` resolved SoundCloud (646 ms), and `ctypes`, `ssl`, `sqlite3`, `hashlib`, `lzma`, `bz2` and `zlib` all import. The interpreter is built with `--enable-experimental-jit=yes-off` (JIT compiled in, off by default), and `-I` ignores `PYTHON_JIT`, so it needs no `allow-jit` entitlement. Developer ID signing and notarisation were **not** tested: no Developer ID yet (N1).

## Plan B vs onedir: the costs

| | Onedir (decision) | Plan B (PBS 3.14 + zipapp) |
|---|---|---|
| Added to the .app | 0 | ~14 MB compressed / 39.5 MB installed |
| Engine download per update | 53.9 MB | 3.07 MB |
| Engine on disk | 123 MB | 24.5 MB unpacked + pycs (or 3.07 MB run as a zip, at +180 ms per call) |
| Mach-O files | 107 (ad-hoc, downloaded) | 1–2 (signed with the app); engine updates contain none |
| Warm `--version` | 165 ms | 67 ms (unpacked + pycs) / 243 ms (zip file) |
| First run | 1.59 s | 68 ms with shipped stdlib pycs and pycs compiled at install time |
| SoundCloud / Mixcloud warm resolve | 561 / 858 ms | 532 / 770 ms (n = 5; network noise dominates) |
| Browser impersonation (curl_cffi) | yes | **no** (adding it means native code to sign; it's 13 MB in the onedir build) |
| TLS roots | bundled certifi | macOS `/etc/ssl/cert.pem`; neither reads the Keychain |
| Who distributes yt-dlp | upstream (sudamp only downloads it) | upstream zipapp, also downloaded; sudamp ships only CPython |

**Other costs to track if plan B is chosen:**

- The install_only build ships only CPython's `LICENSE.txt`. THIRD_PARTY_NOTICES would need the texts for the libraries linked into the interpreter (e.g. OpenSSL under Apache-2.0, SQLite, libffi, mpdecimal, expat, xz, bzip2), taken from PBS's full archives [list not assembled or verified].
- An install step for the engine: unpack the zipapp with the same caps as the skin ZIP reader, run `compileall --invalidation-mode checked-hash` using the bundled interpreter, and write `tree.json`.
- `EngineFlavor`'s argv prefix becomes `<Helpers>/python3.14 -I -B <engine dir>`.
