# Spike L1: Hardened runtime (PLAN M0)

**Verdict: GO** (radio part by the engine agent; yt-dlp spawn added at integration, 2026-10-22, macOS 27.0.1, debug
`.app`).

**yt-dlp spawn (integration).** `make app-hardened` (flags `0x10002(adhoc,runtime)`, no entitlements), then
`build/sudamp.app/Contents/MacOS/sudamp --selftest --engine-check --profile <R1 profile> --json` →
`{"engineVersion":"2026.10.21","output":"2026.10.21","coldMs":219.7,"warmMedianMs":164.5,"ok":true}`. The app spawns the
downloaded, ad-hoc-signed, non-quarantined onedir yt-dlp through `Core.Subprocess` in the scrubbed engine environment.
`log show --last 2m` with the PLAN predicate shows no code-signing, library-validation or JIT messages apart from
amfid's standard ad-hoc `Code=-423` notice, which a scripted check must exclude until Developer ID signing.

## `log show`

PLAN predicate, `--last 2m`, run right after the play:
```
/usr/bin/log show --last 2m --predicate 'process == "sudamp" OR ((process == "kernel" OR process == "amfid") AND eventMessage CONTAINS "sudamp")'
```
(`/usr/bin/log`, because zsh has a `log` builtin.)

| Check | Result |
|---|---|
| Lines from our `sudamp` process | 303 |
| Code-signing, library-validation, JIT, `CS_KILL`, "Library not loaded", "denied" in our process | **0** |
| Error/Fault lines in our process | 1: `CFBundle AddInstanceForFactory: No factory registered for id F8BB1C28-…`, the stock CoreAudio HAL plug-in message every AudioToolbox client logs (not signing-related) |
| kernel lines | 0 |
| amfid lines naming our binary | 1, Default level: `…/build/sudamp.app/Contents/MacOS/sudamp not valid: … Code=-423 "The file is adhoc signed or signed by an unknown certificate chain"` |

**The amfid line** is AMFI's informational notice for any ad-hoc signature, not a hardened-runtime failure: the
process ran its full 60 s. The same window shows the identical notice for other ad-hoc binaries on this machine
(other agents' `sudamp-dev` and `SkinKitTests`). It goes away with Developer ID signing (M8, N1). A strict
`grep "not valid"` over the PLAN predicate will match it, so any scripted version of this gate should exclude
`Code=-423`.

**No JIT is needed.** MPVKit's libmpv is built with LuaJIT, but the option block sets `load-scripts=no` and every
built-in script option to `no` (E1: 0 scripts loaded). Lua is never initialised, so nothing asks for JIT pages, and
`com.apple.security.cs.allow-jit` is **not** needed. Every library is linked statically (`otool -L`: system
libraries only), so library validation has nothing to reject.
