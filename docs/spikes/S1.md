## Rasteriser (`RegionRaster`)

**Rule.** Pixel `(x, y)` is covered if the lattice point `(x, y)`, the pixel's top-left corner, is inside the polygon. Points on left or top boundaries count as inside; points on right or bottom boundaries count as outside. Spans run from ⌈x_left⌉ to ⌈x_right⌉ (exclusive) on scanlines `top.y ≤ y < bottom.y`, using exact integer arithmetic. This is the X11 `mi` edge-table semantics that Wine's `CreatePolyPolygonRgn` uses. Parity with Windows GDI itself is [unverified]: there is no Windows machine, and Winamp's exact call is unknown. No Wine or X11 code was used; the implementation is ours.

**Fill and combine modes:**

- `FillRule`: `.evenOdd`, the DESIGN default (GDI `ALTERNATE`), or `.nonZero` (`WINDING`).
- `PolygonCombine`: `.polyPolygon` puts all polygons in one edge table, as GDI does, so even-odd turns overlaps into holes. `.union` ORs per-polygon masks, which is Webamp's SVG clip-path behaviour.
- The two only differ where polygons overlap.

**Tests** (`swift test` in `spikes/s1-region`: 20 tests in 5 suites, all pass):

- **Edges.** A rectangle's right and bottom edges are excluded. Diagonal left edges include lattice points; diagonal right edges exclude them. Shallow slopes round non-integer crossings with ⌈x⌉. Polygons sharing a straight or diagonal edge tile with no seam and no overlap. Degenerate polygons are empty, and out-of-window vertices are clipped.
- **Shapes.** A concave U, a V notch with diagonal edges and a self-intersecting bow tie.
- **Multiple polygons.** An even-odd poly-polygon gives a hole whatever the orientation. Non-zero depends on orientation. A union keeps the overlap filled.
- **Winamp-style region.txt text.** A 20×8 `[Normal]` with bevelled corners, a bottom notch, a triangle island and a degenerate polygon, plus a `[WindowShade]` section. Also the full-size 275×116 single-pixel corner-cut pattern (31,898 px).
- **Cross-check.** A per-pixel brute-force reference agrees on 400 random polygons per fill rule. Union = OR and poly-polygon even-odd = XOR on 100 random multi-polygon sets.
- **Mutation check.** Changing ⌈x⌉ to ⌊x⌋ makes the hand-computed shallow-slope test and both cases of the reference test fail.

## Click-through: what WindowServer does

`s1probe measure` builds an ordinary window with a 2-pt-per-skin-pixel shaped window above it: 275×116 skin px, a 85×76 px notch cut up from the bottom edge, and a diamond island in the notch. It then asks WindowServer which window a mouseDown would hit at named skin pixels. The shaped window is borderless, `isOpaque = false`, `backgroundColor = .clear`, `hasShadow = true`, with its content as `layer.contents` and `.nearest` filtering, exactly as DESIGN §8.1 plans. Each `ignoresMouseEvents` state gets a fresh window, because "never assigned" can't be restored once the property is set. Raw output: `spikes/s1-region/runs/2026-10-22-measure.json`; three runs gave identical results.

| `ignoresMouseEvents` | Opaque body / island | Alpha-0 notch / corner cut | Notch, lower window hidden | Getter |
|---|---|---|---|---|
| **never assigned** (default) | shaped | **lower window** | **another process's window** (layer 0) | `false` |
| assigned `false` | shaped | **shaped** (pass-through off) | shaped | `false` |
| assigned `true` | lower | lower | another process's window | `true` |

- **Pass-through is WindowServer behaviour, on by default.** Alpha-0 pixels of a non-opaque window don't take clicks, and those clicks reach whatever is below, including other apps.
- **Assigning `ignoresMouseEvents = false` turns it off.** The getter returns `false` in both states, so code can't tell them apart. **`SkinWindow` must never assign the property.**
- **The hit shape follows the content at run time.** One live window switched full → notched → full → notched; the notch spot answered shaped → lower → shaped → lower, with no API call. Skin switches and shade toggles need nothing extra.
- **A `hitTest` override can't produce pass-through.** WindowServer never consults the app. Synthesised `NSEvent`s sent to the window show that the override only stops the content view getting `mouseDown` on alpha-0 pixels, while WindowServer's answer stays the same. In the default state such clicks never reach us anyway. Under `ignoresMouseEvents = false` the override would just swallow them. **Decision for DESIGN §8.2: rely on WindowServer behaviour, with no `hitTest` override.** `Layout.hitTest` still maps clicks on opaque pixels to hotspots.
- **Conditions.** The screen was locked during the run (`CGSSessionScreenIsLocked = 1`), so the lock shield (layer 2004) and 6 other windows sat above the probe. A plain query returns the shield. The measurement passes the window directly above the probe as `belowWindowWithWindowNumber`, which by the API's definition excludes it and everything above, so the answers are about the probe's own stack. The display was 1x (1920×1080); 2x Retina wasn't measured. The mask's alpha is strictly 0 or 255; partial-alpha thresholds weren't explored, and the composer never produces them.

## Shadow

Own-window capture works without Screen Recording permission. The capture uses `CGWindowListCreateImage`, obsoleted in the macOS 15 SDK and looked up at run time; it is a probe-only tool, not for the app. Shadow alpha (0–255), with skin y = 119 meaning 6 pt below the bottom edge:

| Stage (same window unless noted) | Below the left leg | Below the notch | Inside the notch, 3 px under its top edge | Notch interior |
|---|---|---|---|---|
| 1. Full rectangle | 18 | 18 | (opaque content) | (opaque) |
| 2. Switched to notched, **no** `invalidateShadow()` | 18 | **0** | **18** | 0 |
| 3. Then `invalidateShadow()` | 18 | 0 | 18 | 0 |
| 4. Back to full, no `invalidateShadow()` | 18 | 18 | (opaque) | (opaque) |
| 5. New window created notched | 18 | 0 | 18 | 0 |

The shadow follows the alpha shape. The notch's walls fall off exactly like the outer edges, the top bar casts shadow into the notch (23 → 6 → 1 → 0), and the island has its own shadow (`runs/2026-10-22-shadow-notched-no-invalidate.png`). On macOS 27 the shadow was recomputed after a content change without `invalidateShadow()`: the stage 2 and 3 captures are byte-identical. Keep calling it as DESIGN says; it's documented and cheap. Only the inactive-window shadow was measured (the probe never activates). The larger key-window shadow is checklist step 6.

## Manual checklist (owner, about 5 minutes)

Do this while logged in and unlocked, on any display; note whether it's Retina. Nothing needs permissions, and nothing changes system settings.

1. **Start.** `cd spikes/s1-region && swift run s1probe manual` (the first build takes about 30 s). A window titled **"S1 lower window"** shows orange stripes. A teal shape with a notch and a diamond floats over the stripes. Every click is logged at the bottom of the window and in the terminal.
2. **Default state** (`ignoresMouseEvents: unset`, override unticked):
   - Click the **orange stripes inside the notch** → expect `LOWER window got the click`.
   - Click the **teal body**, then the **diamond** → expect `SHAPED window got the click … opaque pixel` each time.
3. **Explicit false.** Choose `ignoresMouseEvents: false` (the shape is recreated). Click inside the notch → expect `SHAPED … TRANSPARENT (alpha 0) pixel`, meaning pass-through is off.
4. **True.** Choose `true`. Click the teal body → expect `LOWER`.
5. **Other apps.** Choose `unset`. Drag the teal shape by its body over a Finder window or a desktop icon, then click that item through the notch. Expect Finder to select it or come forward, and s1probe to log nothing.
6. **Shadow.** Back over the stripes: the shadow should hug the shape. There should be no shadow band under the notch's gap, and a faint shadow inside the notch below the top bar and around the diamond. Click the body once so the shape is active and check again. Press **Swap shape** twice; does the shadow follow each time before **invalidateShadow()** is pressed?
7. **Optional: hitTest override.** Tick the override with `unset` → a notch click still logs `LOWER`. Choose `false` with the override ticked → a notch click logs nothing; the click is swallowed.
8. Quit with ⌘Q and paste the terminal output under *Manual results*.

**Pass:** steps 2, 3 and 5 behave as described. **Fail:** a notch click in step 2 or 5 is logged by `SHAPED`, or doesn't reach the app below. On failure, apply PLAN's NO-GO plan: region.txt moves to v1.1 and windows stay rectangular.

## Implications for M4/M5

- **M4 (SkinKit):** move `RegionRaster` into SkinKit together with its tests, and port macamp's tolerant parser as planned (this spike's parser is deliberately minimal). Keep both `PolygonCombine` modes. The skin bench should count museum region.txt files with **overlapping** polygons: only there do GDI-style even-odd (holes) and Webamp's union (filled) differ, and Winamp's real behaviour is [unverified].
- **M5 (SkinWindow):**
  - Never assign `ignoresMouseEvents`; use no `hitTest` override for pass-through.
  - Keep the composed frame's alpha binary (sheets are normalised with alpha ignored, region pixels set to alpha 0, `.nearest` filtering).
  - Call `invalidateShadow()` after skin, shade or region changes.
  - Keep the kill switch: with it on, the frame is fully opaque and the window is rectangular.
  - The M5 manual checklist's "shaped-skin click-through" item can reuse steps 2, 5 and 6.
- **`s1probe auto`** posts real HID clicks for every combination once the terminal has Accessibility permission. It needs no prompt and restores the pointer afterwards. It is untested, and granting that permission is the owner's call.
